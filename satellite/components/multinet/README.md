# `multinet` — Stage B external component

An ESPHome external component wrapping esp-sr's MultiNet7 for on-device recognition of the
hot command set. **This does not exist off the shelf.** Nobody ships a MultiNet component
for ESPHome as of September 2026.

The precedent to follow is [esphome-audio-stack](https://github.com/n-IA-hane/esphome-audio-stack),
which pulls esp-sr into ESPHome through the IDF component manager for echo cancellation and
the audio front end, on S3 and P4 with PSRAM. The same path works here:

- `espressif/esp-sr` as a managed IDF component
- a `model` partition appended through ESPHome's `esp32: partitions:` list, reserve 4 MB
- the command table generated by esp-sr's `multinet_g2p.py` from `../../commands/commands.yaml`
- a microphone listener alongside the ones `micro_wake_word` and `voice_assistant` already
  attach — the audio sharing is most of the work

Scope: larger than a typical custom component, mostly because of the audio sharing and the
partition. Evenings for a couple of weeks rather than a weekend.

## What it must do on a hit

In this order, and the order is the design:

1. `voice_assistant.stop` — cancel the streaming pipeline so the brain never sees a duplicate
2. `homeassistant.action` over the native API — needs "Allow the device to perform Home
   Assistant actions" enabled on the satellite's HA device page
3. play the matching clip from flash
4. emit the `satellite_hit` event with the command id and the top two probabilities

Act only when the top candidate clears `min_probability` **and** leads the second by
`min_margin`. Below either, it is a miss: do nothing and let the streaming path, which has
been running the whole time, simply continue.

## Shadow first, and it is not optional

For the first weeks MultiNet predicts and does not act. The streaming path acts, and
because the audio was streamed anyway, the brain scores every on-device prediction against
the guard chain's decision for the same utterance. A command is promoted to acting only
when its shadow record shows zero polarity disagreements and an agreement rate set from the
data.

## Fallback if this stalls

`micro_wake_word` runs several models at once and custom ones can be trained from synthetic
Piper samples. That gives three to five on-device commands with zero C++. It does not scale
to fifty, but it is a real fallback rather than a blocked project.
